# 要件まとめ

優先度は3段階。
- **P0**: MVPに必須。これがないと製品として成立しない
- **P1**: PAD等の既存製品に対する差別化要素。MVP後の主軸
- **P2**: 将来的にあると良いが、後回しにしても致命的ではない

---

## 1. フロー編集・実行の基本

| 要件 | 優先度 | 備考 |
|---|---|---|
| GUIでのフロー編集(ノード追加・接続・パラメータ設定) | P0 | |
| 座標指定によるクリック/操作 | P0 | 最も単純だが解像度依存。保険的機能として必須 |
| UI要素選択(UI Automation)によるクリック/操作 | P0 | 座標より頑健。標準Windowsコントロールで有効 |
| 完全一致の画像認識・待機 | P0 | PAD相当の最低ライン |
| ステップ実行・ブレークポイント | P0 | デバッグ体験の根幹。初心者・上級者双方に必要 |
| 変数・分岐(If/Else)・ループ | P0 | |
| フローの保存・読み込み | P0 | ファイル形式は[architecture.md](architecture.md)参照 |
| 実行ログ・エラー箇所の可視化 | P0 | どのステップで何が起きたかが追えること |

## 2. 認識精度の差別化(このプロジェクトの核)

| 要件 | 優先度 | 備考 |
|---|---|---|
| 特徴点マッチング(ORB/AKAZE)による画像認識 | P1 | 拡大縮小・多少の回転・ノイズに耐性。まずここ |
| マルチスケールテンプレートマッチング | P1 | 特徴点マッチングと併用するハイブリッド方式 |
| 軽量AI類似検索(embeddingベース) | P1 | 特徴点マッチングで精度不足の場面向け。ONNXモデル |
| 完全一致→特徴点→AIの段階的フォールバック | P1 | 速度と精度のトレードオフを自動で調整 |
| 認識パフォーマンスのプリセット切替(低/中/高) | P1 | 内部的にはスケール数・タイムアウト等のプリセット値 |
| 認識パフォーマンスの詳細パラメータ調整 | P2 | 上級モードでのみ表示 |

## 3. 初心者/上級者の両立

| 要件 | 優先度 | 備考 |
|---|---|---|
| 簡易モード(情報密度を絞ったUI) | P1 | 同一フローデータを異なるビューで表示する設計必須 |
| 上級モード(詳細パラメータ・座標直接編集) | P1 | |
| GUI⇄コード(DSL/YAML)相互変換 | P1 | コードは人間が書ける形式にする(JSON直書きは避ける) |
| 自然言語からのフロー生成(バイブコーディング) | P2 | コード層ができてから着手 |
| ノードグラフ表示 / 直列リスト表示など複数ビュー | P2 | 表示方式をユーザーが選べる。データモデルは共通 |

## 4. 多言語対応

| 要件 | 優先度 | 備考 |
|---|---|---|
| UI文字列の英語/日本語切り替え | P0 | 最初から文字列をキー化しておく。後付けは工数増大 |

## 5. カスタムコード

| 要件 | 優先度 | 備考 |
|---|---|---|
| JS(サンドボックス)によるスクリプトノード | P1 | 入出力を明示バインドし、ファイルシステム等への無制限アクセスは禁止 |
| Pythonによるスクリプトノード | P2 | 権限分離が難しいため後回し。外部プロセス+制限付き実行を検討 |
| スクリプトノードを含むフローのインポート時警告 | P1 | セキュリティ上、無警告での実行は避ける |

## 6. 環境・実行基盤の考慮

| 要件 | 優先度 | 備考 |
|---|---|---|
| 管理者権限で起動しているアプリへの対応 | P0 | UIPIにより非管理者権限からは操作不可。本体を管理者権限起動できるオプションが必要 |
| DPIスケーリング対応 | P0 | 座標系の正規化。後回しにすると手戻りが大きい |
| マルチモニタ構成変更時の例外処理 | P0 | モニタ切断でウィンドウ集約→座標無効化。自動続行せず警告して一時停止 |
| 座標の保持形式(モニタID+相対座標) | P0 | 上記の前提となるデータ設計 |

## 7. セキュリティ

| 要件 | 優先度 | 備考 |
|---|---|---|
| 秘密情報(パスワード・APIキー)の専用管理機能 | P1 | Windows Credential Manager連携、フロー内平文保存の禁止、マスキング表示 |
| フローファイルのスキャン(危険操作の検知) | P1 | スクリプトノード・外部プロセス実行ノードなどを検知し警告 |
| 他人が作ったフローのインポート時確認UI | P1 | 実行前に含まれる操作内容を一覧表示 |

## 8. エラーハンドリング

| 要件 | 優先度 | 備考 |
|---|---|---|
| ノードごとのリトライ回数・間隔設定 | P0 | 画像認識は完全一致より誤検出・見逃しが起きやすいため必須 |
| 失敗時の挙動選択(即失敗/リトライ/スキップ) | P0 | |
| try/catch的なエラーハンドリングノード | P1 | 特定ステップ以降の例外を捕捉して代替処理へ分岐 |

## 9. データ管理・配布

| 要件 | 優先度 | 備考 |
|---|---|---|
| フローファイルのバージョン管理(Git差分に強い形式) | P1 | ロジック部分とレイアウト(座標)部分をファイル内で分離 |
| インストーラ・自動更新 | P2 | MVP後 |
| フロー共有(マーケットプレイス的なもの) | P2 | 将来構想。まずは個人利用で完成度を上げる |

---

## スコープ外(明示的に対象外)

- Office製品・Power Automate Cloud等Microsoft資産との連携
- Windows以外のOS対応(将来Rust側の実行エンジンを切り出して検討する余地はあるが、MVPでは考えない)
